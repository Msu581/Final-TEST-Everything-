02Rule set & run Every rule below is applied to every gradesheet. Nothing is sampled.
Rules in force
Match key Registration No.  ·  Credit structure T-P-PR, exact position (0-4-0 ≠ 0-0-4)  ·  SGPA / Percentage exact to 1 decimal  ·  Student name exact string  ·  Subject name normalises & ↔ and, spacing and case (cosmetic = variant, otherwise mismatch)  ·  Marks · Grade · Grade Points · Credit Points exact.
Subject detection reads the TR's column blocks structurally — a block counts if it has a course name, code, credit line or mark, so an OJT column with no course code is still counted.  ·  Subject pairing uses the course code first, then falls back to the course name (codes differing between TR and gradesheet are noted, not treated as a missing subject).
Derived totals (not in the TR — computed from the TR's subjects): Maximum Marks = subjects × 100, Total credit line Σ T-P-PR, Total Credits Σ(x+y+z), Grand Total Credit Points = 10 × Total Credits — each checked against the PDF's printed totals.  ·  Blank fields (TruScholar glitch) are always flagged — even when PDF and TR are both blank. A subject row that prints Code, Name and Credits but leaves Marks (or Grade / GP / CP) empty is still read, and the empty cell is reported as an error. An identity field whose label is not printed at all (e.g. a gradesheet with no ABC ID row) is reported as a format difference (N/A), not a blank-data error.
Verification keeps running while this tab is in the background — switch tabs or minimise the window and it carries on to the end rather than pausing. Live progress also appears in the tab title, and the browser will warn you before you close the tab mid-run.
